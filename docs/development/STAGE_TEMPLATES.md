# ステージの素材セットと部屋テンプレート

## 現在の構成

| データ | 保存先 | 内容 |
| --- | --- | --- |
| StageTheme | data/stage_themes/workshop.tres | 床、壁上面/正面、角、扉枠、室外基礎、反復寸法、柱寸法、床色 |
| FieldDefinition | data/fields/*.tres | 床領域、壁矩形、壁IDと材質、開始位置、配置物、素材セット |
| RoomTemplate | data/rooms/*.tres | 表示名、フィールド、扉の位置・到着位置・接続先 |
| StagePlacement | FieldDefinition.placements | 配置ID、足元位置、画像、ローカル描画矩形、独立した衝突矩形、背景/前景、照明 |

現在の2部屋を移行済み。共通Builderが検証済みコピーから組み立てる。素材セットを持つ未知の部屋IDも描画可能。既存対戦は同じ工房素材セットを参照し、配置を維持する。旧式の壁番号によるTexture2D指定も互換のため残す。

## 部屋を追加する手順

1. data/fieldsの工房定義を複製し、field_id、床領域・壁・開始位置を編集する。
2. wallsとwall_idsを対応させる。並べ替えは矩形とIDを一緒に移動する。wall_materialsはIDをキーにcover/top/faceを指定する。
3. themeに素材セットを指定する。素材だけ変更するときは衝突矩形を編集しない。
4. 家具・照明はStagePlacementのResourceとしてplacementsへ追加する。衝突なしはcollisionを空のRect2にする。light_radiusが正ならPointLight2Dを生成する。
5. data/roomsにRoomTemplateを作り、表示名と左右の扉を設定する。相手側にも対応する接続先を定義する。
6. ExplorationRooms.ROOMSへ登録する。部屋一覧の自動検出やフロア自動生成は未実装。
7. 開始位置・到着位置・扉までの到達性と、描画の重なりを確認する。

例：位置(700,300)、visual_rect(-24,-48,48,48)、collision(-20,-10,40,20)なら、画像は足元から上へ描画し、衝突は足元だけに設定できる。光のみの配置はtexture未指定でよい。画像寸法は照明半径・衝突を変更しない。

## 移動範囲と寿命

探索はconstrain_to_floorを有効にし、床矩形の和集合の外をsolidとして扱う。これは中心点の領域制限で、壁際の身体半径による余白は壁矩形の判定が担う。壁を置き忘れても中心が暗い室外へ移動しない。弾にも同じsolid判定を使う。

配置物と照明はStageBackground/StageForeground内に生成し、部屋の切り替え時に破棄・再構築する。衝突はruntime_definition内の配置データを参照する。無効な配置ID、寸法、壁ID、開始位置の家具との重なり、扉データなどは組み立て前に拒否する。

## まだ提供していない機能

- 内角・外角・T字の自動選択と自動壁生成。
- 人物と家具の足元による動的な前後関係。現状は背景/前景の固定2層。
- 上下の扉描画。現在は不正な方向を検証で拒否する。
- 家具の操作・破壊・開閉、部屋別の永続状態、ランダムなフロア接続。
- 光の遮蔽、影を落とす家具、完成見本用の新素材と配置。

StagePlacementはこれらの完成を意味せず、素材制作と一室の構築を進めるための配置基盤。追加のAPI生成は行っていない。
