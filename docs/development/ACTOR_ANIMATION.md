# キャラクターの状態とアニメーション

更新: 2026-09-21。標準AnimationTreeに、8人共通の待機・歩行キーフレームとパーツ表示を接続。
この資料は現行の拡張手順。戦闘ルールは[GAME_RULES](../design/GAME_RULES.md)、検証方法は[TESTING](TESTING.md)。

## 責務とデータの流れ

```text
人間入力 / CPU判断
  → CombatCommand → CombatSession / Player（行動の可否・時間・効果を確定）
  → Player.visual_snapshot()（表示用の値へ変換）
  → actor_visual_state.gd（身体・武器の表示状態の優先順位）
  → actor_animation_state.tscn（独立した2つのAnimationTree）
  → player_animation.gd → PartsのSprite表示（待機・歩行）/ 既存の専用回避描画
```

戦闘側のHP・弾薬・無敵・回避・装填タイマーが正本。アニメーションの再生完了、クリップ長、
再生速度を根拠にそれらを変更しない。AIの追跡・退避などの判断状態は、この表示グラフへ入れない。
現在の戦闘処理をすべて汎用FSMに置換したものではなく、既存の行動判定を維持した表示状態の分離である。

`actor_visual_state.gd` はNodeやPlayerを参照しない値のスナップショット。
生存・移動意図・速度・照準・方向・回避時間と操作制限・装填時間・近接中・無敵・装備有無を渡す。
キャラID・盾表示・レリックの色も値で渡し、描画側は可変の戦闘辞書やインベントリを読まない。
移動判定は従来どおり移動入力の有無であり、壁に遮られた実速度による接地補正は未導入。

## 並行する状態

|グラフ|状態|要求の優先順位|
|---|---|---|
|BodyTree|idle / move / roll / dead|死亡 → 回避中 → 移動 → 待機|
|WeaponTree|disabled / ready / fire / reload / melee|死亡 → 近接中 → 丸腰 → 装填中 → 射撃反動中 → 通常|

回避中でも装填タイマーは進むため、`roll + reload`を許す。
リナの回避は0.38秒、操作制限は先頭0.31秒なので、終盤は`roll + fire`となる。
武器の可視性はスナップショットの操作制限から独立して求め、BodyTreeがrollだから一律非表示にはしない。
fireは発射イベントによる既存反動の持続期間であり、発射間隔用の`state.shot`とは異なる。
連続発射は同じfire状態でもクリップを先頭へ戻す。単なる再描画では再生を戻さない。
近接と装填が重なる場合は近接表示を優先するが、装填の戦闘処理は中断しない。

死亡はhurt()から即時通知する。死亡したActorは次の戦闘tickで更新対象から外れるため、
次tickの表示更新に依存しない。死亡専用の絵はまだなく、身体は通常姿勢・武器は非表示となる。
ラウンド初期化で両グラフ、歩行位相、反動、装填通知をリセットする。

## Godotで編集する場所

`scenes/visuals/actor_animation_state.tscn`を開く。

- `BodyPlayer` / `WeaponPlayer`：AnimationPlayer。クリップの編集入口。
- `BodyTree` / `WeaponTree`：AnimationTree。Tree RootのStateMachineで状態と遷移を編集。
- 各遷移は独立したResource。1本の編集が他の遷移へ波及しない。
- 初期化・回避/死亡への即時中断は`start()`、通常の切り替えは`travel()`。再生操作はAnimationTree側へ集約する。

BodyPlayerは`Parts/Lean/Body`の回転・拡縮と、`Parts/Foot0` / `Foot1`の位置をキーで動かす。
リナの正面パーツを初期配置しているため、このシーンだけでもAnimationPlayerのタイムラインで
プレビューできる。実行時は`character_parts.gd`が8人・方向ごとの画像へ差し替える。
Partsの親はNode2Dとし、Actorの位置・拡大率を正しく継承する。

- idle：2.6秒の呼吸。縦倍率0.975〜1.028、回転±0.03rad。足は固定。
- move：基準0.52秒の交互歩行。縦倍率0.94〜1.025、回転±0.065rad、足の持ち上げ最大4.4px、前後振幅3.6px。
- idle→move：0.12秒、move→idle：0.20秒で数値トラックを補間。
- roll→idle/move：0.10秒。回避・死亡への移行は補間待ちをせず即時に中断する。
- roll/dead：通常パーツ用トラックを中立へ戻す。roll中はパーツを隠し、既存の回避絵を描く。

body_stateはStateMachineの現在ノードから得る論理状態。姿勢の補間途中でも次の行動を受け付ける。
武器側は従来の離散トラックを維持。BodyPlayerの数値トラックへ武器の状態名を混ぜない。

`character_parts.gd`は移動方向に歩幅を合わせ、補間中も少なくとも片足の支持面を接地させる。
進行方向への傾きは時間刻みに安定な減衰式で加え、基準速度で最大0.09radとする。
体に追従する武器の位置補正は最大2pxで、照準角度は変えない。
身体の拡縮の支点は足元。髪・頭・腕はまだ胴体画像と一体であり、独立したまばたき等は未制作。

両Treeは手動更新。`Player.advance_visual(dt, moving)`から時間を1回進め、
`sync_visual()`や発射直後の通知は時間0で評価する。
Godotのtravelは遷移元のサンプル後に遷移を解決するため、状態変更時は0秒の評価を挟み、
同じtickで遷移先のトラックを反映する。歩行の時計は移動速度/205に追従する。
停止直後の再入力は`next()`で保留中の遷移を進める。ポーズ・結果画面・Hub停止中は自動で再生が進まない。

## 動作・敵を追加する手順

1. 行動が移動、武器操作、全身のどこに属するか、他の動作と同時に成立するかを決める。
2. 戦闘側で開始・終了・中断・可否を確定し、必要な値をスナップショットへ追加する。
3. `body_target()` / `weapon_target()`に表示上の優先順位を追加する。
4. 該当AnimationPlayerにクリップ、StateMachineにノードと必要な直接遷移を追加する。
   `travel()`の未接続先へのテレポートに依存せず、瞬時に中断可能な経路を明示する。
5. 描画パーツまたは既存描画への接続を追加し、組み合わせ・中断・初期化のテストを増やす。

新しい敵はPlayerを継承する必要はない。同じスナップショットを構築するアダプターを用意する。
状態名の契約に合う敵はこのシーンを再利用し、飛行・詠唱など異なる動作を持つ敵はグラフと
クリップ、描画を別シーンとして用意する。現行の8人用の画像読み込みへ未知のキャラIDを渡さない。
共通化するのは入力契約と更新境界であり、全種族の状態を単一グラフに詰め込まない。

## 次の制作段階

通常の戦場カメラは全体を収める設定を維持する。標準デスクトップウィンドウは1120×800へ変更し、
従来の600px高による縮小を軽減した。Godotの埋め込み実行サイズはエディター側の表示領域にも依存する。
[通常サイズの描画記録](../art/reviews/dynamic-motion-2026-09-21/README.md)。

胴体・足のノード化と、8人の待機・歩行・発進/停止の補間は実装済み。
強化後の振幅・テンポはユーザー採用済み（2026-09-21）。今後必要ならキャラ固有のクリップへ分ける。
さらに頭・髪・腕のパーツ分割と描き足しを行い、まばたきや装飾の独立した揺れを加える。
戦闘の正本へ影響させずにクリップと遷移を変更できることが、この基盤の目的である。
新しい敵、ひるみの戦闘ルール、死亡モーション、追加画像生成は今回の実装範囲に含まない。

### 仮組み込み：リナ v8（8方向の走行・待機・回避、2026-09-26、既定は無効・未採用）

`scripts/visuals/character_rig8.gd`（当初の名前は rina_run_rig.gd）は、リナの待機・走行・回避を生成パーツの8方向表示に置き換える試験表示。走行は弾み「強」8コマ、待機は2.6秒周期の呼吸8コマ、回避は6コマ（踏み込み→踏み切り→飛び込み→着地前→着地→立ち直り、0.04/0.10/0.20/0.26/0.32秒で切替、0.04〜0.26秒は最大6px浮く）。
既定は無効で、ゲーム中に V キー（F8 は Godot エディターの実行停止と重なる）、または起動引数 `-- --rina-run` で切り替える。他キャラは従来の素材のまま。回避は移動方向で向きを選び、操作制限中（銃が隠れている間）は両腕を前へ伸ばす。
ポニーテールとスカーフの垂れは別画像で、`update_swing()` が Actor ごとの減衰ばね（前進のなびき・付け根の加速度・ゆるやかな揺れ）を毎フレーム計算し、`draw_part()` が格子に分けて付け根から毛先へ曲げて描く（スカーフは速さに応じてはためく）。状態は player_animation の `rig_swing` に持ち、`reset()` で消去。
向きは照準角で8方向（45°刻み、前の向きを22.5°+8°まで保つ）。描き分けは側面・斜め前・正面・斜め後ろ・背面の5向きで、西・南西・北西は右向きの反転。
重なり順は向きごと：側面・斜め前は 遠側の腕 → 体 → 銃 → 頭 → 手、正面は 体 → 銃 → 頭 → 両腕、斜め後ろ・背面は 銃と両腕 → 体。
銃は Weapon の変換（照準角・反動・装填の傾き）をそのまま使い、`place_weapon()` が grip（Weapon ローカル (8,0)）を手の位置へ移すため、発射演出の銃口位置も描いた銃と一致する。Weapon/Sprite は隠す（読みやすさ用の輪郭シェーダーは未適用）。
コマは本編の歩行位相（6で1周期）を8コマへ割り当て、後退は逆順。素材と各コマの手・肩は `assets/first-workshop/rina-run-8dir/`（制作記録の `build_run_cycle_v8.py` が書き出す）。
制作記録：[リナ体型と独立パーツ](../art/reviews/rina-parts-2026-09-25/README.md)（v8）。

2026-09-26 一般化：描画は `scripts/visuals/character_rig8.gd`（旧 rina_run_rig.gd）。`data/character_rigs.json` に登録したキャラが対象で、素材と `rig.json` は `tools/character_rig/build.py <name>` が設定ファイル（`tools/character_rig/characters/<name>.json`）から書き出す。手順は [キャラリグの作り方](../../tools/character_rig/README.md)。揺れ物は種類（hair/cloth）で揺れ方を変える。
近接（ナイフ）：押した瞬間（Slash 表示の立ち上がり）から0.26秒、4コマの体（踏み込み→振り抜き→戻り→構え）を再生し、照準方向へ最大7pxの見た目の踏み込み。奥の手がナイフを照準の -60°→+60° へ振り抜き（銃は手前の手のまま）、当たり判定と同じ扇形（半径64・左右70°）の外周から刃の位置まで斬撃の弧を0.2秒で消す。仮組み込み中は従来の白い弧（Slash）を隠す。

キャラの大きさ案D（試験、既定は無効）：参考動画ではキャラが画面高の約13%、現行の探索画面は約8%。C キーまたは起動引数 `-- --size-d` で、探索カメラの倍率を 1.2→1.45（`exploration_camera.gd` の `ZOOM_D`）、仮組み込みのリナの描画を足元中心に1.1倍（`CHAR_SCALE_D`、当たり判定は不変）にする。見える範囲は縦約414px。他7人・敵の表示倍率は変えない。遊び方への影響を確かめるための一時設定で、採否は未決定。

参照：[AnimationTree](https://docs.godotengine.org/en/stable/classes/class_animationtree.html)、
[StateMachinePlayback](https://docs.godotengine.org/en/stable/classes/class_animationnodestatemachineplayback.html)。

## 探索の工房番機

番機は人間用AnimationTreeを使用せず、exploration_enemy.gdの`enemy_visual_snapshot()`から位相・残り時間・固定角度を値として渡し、sentry_visual.gdで仮の身体と工具を描く。描画側に独立した時計・攻撃通知・戦闘状態の書き戻しはない。停止時も同じ姿勢を保つ。正式素材への置換ではこの入力と戦闘時間を維持し、画像の再生長から攻撃時刻を逆算しない。工房番機以外への共通化は次の敵の要求を確認して行う。


## 通常敵の画像表示

現在は[アニメーションv2](../art/production/enemy-animation-v2/README.md)の専用32コマ×2種を使用する。各4方向に歩行4コマ・構え・攻撃・復帰・倒れを持つ。左右は別画像。enemy_sheet_visual.gdの領域と原点で描画し、全身メッシュ変形は撤去した。実移動距離で38px周期を進め、停止中・壁押しでは足運びを進めない。

構え・攻撃は戦闘時間、被弾反応は被弾後の短い時間へ追従する。撃破時はenemy_death.gdへ値のスナップショットだけを渡す。残像NodeはActorや攻撃判定を持たず、0.85秒で退色。exploration.gdが停止条件に従って更新し、離室・再挑戦で消去する。敵退役と報酬を演出待ちにしない。

専用関節リグではなくコマ方式を採用。原画の切出し・倍率・未確認事項は制作記録を参照。


撃破後の消失演出: 本体は0.85秒で退色し、番機は短い火花6粒と埃、トカゲは控えめな土色の粒子を残す。全体は1.1秒で消去。粒子は描画のみで、追加SE・衝突・報酬遅延なし。停止・離室・再挑戦の消去は従来の撃破表示と共通。

### 独楽の鋳造機の砲撃表示

boss_cannon_art.gdが生成シートの切出し・砲口原点・弾・8コマ爆発を管理する。判定は床平面、発射直後だけprojectile_art.gdが砲口高さから0.16秒で判定位置へ補間する。furnace_warden_visual.gdは後方の閃光→本体→前方閃光の順に描画し、全身を平面回転しない。着弾はcombat_sessionからcannon_impactイベントを1回だけ出し、combat_visualsの上限付きcustom_effectsで戦闘dt更新する。素材の登録値と通常倍率確認画像は[制作記録](../art/production/furnace-warden/README.md)。

起動演出はexploration_boss_flowが戦闘停止中の時計と排圧イベントを管理し、furnace_warden_visualへstartup進行を渡す。暗い本体の点灯・振動・煙を既存素材で表す。報酬箱はexploration_chestが登録済み4姿勢を共通倍率で描画し、独立_processを使わず探索dtで落下/開封/粒子を更新する。
