# Visual Hub Web Live 実装・検証（2026-09-13）

## 合意した要件と実装

Webを操作の中心にし、比較への追加をせず一覧で素材を確認する。

|対象|実装|
|---|---|
|武器38種|名前・本体画像・実ショップ価格/非売品・占有形状。装備/発射、弾丸/軌道、命中/固有効果、リロードの4列|
|レリック35種|画像・名前・ゲーム定義の効果文・占有形状|
|キャラ8人|待機・歩行・回避の3列。装備武器、照準、移動方向、背景、同期条件を一括変更|
|共通操作|Web実描画、再生/停止、速度、1ステップ、倍率/枠に収める、クリック拡大、条件のローカル保存|

初回のエンジン/PCK読込後は撮影を介さない。DOM位置と条件をJavaScriptBridgeへ送り、1つのGodot Webエンジンで表示範囲だけを描画する。上限24枠。画面外のAdapter/Viewportを解放し、復帰時は現在の6秒ループ時刻へ合わせる。
既存Player/CombatSessionと描画処理を共有。価格はShopCatalog.price、形状はBuildGrid.shape_ofを呼ぶ。ゲーム定義や武器性能の複製はない。
従来の撮影Compare・History・レビュー・ネイティブHubは維持した。今回の更新を初めて開いたときは武器一覧を表示し、以前の撮影Compareを自動再撮影しない。

## Webパックと配布分離

既存の `web-build/index.wasm` の版を検査し、実際のブラウザログでもGodot 4.7.2.stable.official.ed1daf0bfを確認した。single-threaded / Compatibility / WebGL 2。
通常ゲームのexportを基に、Hubスクリプトと読取用原本を加えた専用PCKを `.local/visual-hub/live/` へ生成する。起動Sceneと透明描画設定は専用PCK内部だけで変更する。project.godot、ゲームのデータ・描画ソース・素材を変更していない。
PCKは別名へ完成させてから置換する。起動スクリプトと「実描画を更新」から再収集・再パック・ページ再起動する。元のデータとパックの版が異なる場合は案内を出す。

## 実装中に見つけて修正した点

- 配布用WebエンジンはSceneのコマンドライン上書きを許可しない。起動Sceneを専用PCK内部で設定して解消。
- iframeの透明背景はブラウザ側で白くなるため、表示セル領域だけをCSSでクリップし、Webの文字や操作部を覆わない構成にした。
- 同一武器の発射と命中枠でキーが重複していたため、用途別のscenarioで独立化した。
- stretch有効なSubViewportの直接サイズ変更による警告を除去。
- 一覧では文字が小さくなるため、専用画面で冗長な見出しと旧カテゴリメニューを省き、装備・弾道・キャラごとに表示範囲を調整した。

## 制約・後続

- 初回にWebエンジン約39.5MBとHub PCK約30.7MBをローカル読込する。素材・スクリプト変更はパック更新が必要。表示条件だけの変更に再撮影/再パックは不要。
- 6秒ループ/60Hz固定刻み/seed719。任意の長時間履歴の操作は従来Hub側で確認する。
- 標的は死亡しない検証用。通常の命中場面は標的位置を固定。「固有効果・引き寄せ」では固定せず、既存効果処理へ任せる。累積ダメージ等はループごとにリセットする。
- ブラウザ全種・低性能端末の性能は未検証。Webとネイティブの最終的な描画差は両方で確認する。
- 現在のバッチ処理は単一ローカル利用が前提。完全依存グラフ、独立VFX/UIギャラリー、音声試聴、自動監視は後続。

API仕様の確認にはGodot公式の [JavaScriptBridge](https://docs.godotengine.org/en/4.6/classes/class_javascriptbridge.html) と [Web Engine API](https://docs.godotengine.org/en/latest/tutorials/platform/web/html5_shell_classref.html) を参照した。
現行の起動・操作は [README](../../../tools/visual_hub/README.md) を参照。
