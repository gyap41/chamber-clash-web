# Visual Hub スクロール時の白い帯の修正

2026-09-13。過去の検証とは別の、今回の表示方式変更の記録。

## 原因と変更

旧方式は固定iframeのGodot描画位置とDOMカードのclip-pathを別々に更新していた。スクロール時に新しいクリップ領域へ古い描画位置が露出する時間差があった。

単一Godot Webエンジンを維持し、スクロール座標に依存しないアトラスを描画する。RenderingServer.frame_post_drawから同期イベントを送信し、各カードのCanvasへ描画完了した画素を転送する。カードと映像は同じDOM要素としてスクロールする。古いレイアウト世代やサイズ不一致のフレームは転送しない。物理・武器・キャラのゲーム側処理は変更していない。

## 今回の検証

- TypeScript型検査、Vite production build成功。
- Godot 4.7.2 Compatibility用Webパックの再生成成功。
- tests/visual_hub_live.gd成功：24キャラ枠、装備切替、停止時計、画面外対象の解放。
- Codex内蔵ブラウザの実描画確認：武器一覧の再生・停止、PageDown/PageUp、拡大1枠。キャラ一覧のスクロールと新規行の描画完了。
- DOM Canvasへの転送、一覧8〜16枠と拡大1枠の描画を確認。撮影した画面に白い帯・カード外への漏れはなかった。
- 描画転送後も確認時の定常表示は約139〜144fps。ただし端末共通の性能保証ではない。

## 制約

初めて画面に入る対象にはプレビュー生成待ちがある。高速スクロールの全フレームを動画解析した検証ではない。端末・ブラウザごとの追加確認は可能。反映にはページ再読込が必要。通常ゲームの起動Scene、ゲーム定義、描画コードは変更していない。
