# フィールド定義と配置の分離

実施: 2026-09-12。直前の拡張リファクタリングの未コミット変更を維持して追加実装した。
変更前の2シーン・補給シーン・main・現行4資料は
`.local/backups/field-separation-20260912-120001.zip` に保存した。

## 実装

- FieldDefinition（Resource）に初期配置を集約し、固定2フィールドをdata/fields/duel.tresとvalidation.tresへ移した。
- FieldBuilderが定義の独立コピーを検証し、床・壁・出現地点・補給候補地点を生成する。
- Arenaの移動/衝突/射線/危険地帯APIは維持。戦闘は固定Resourceかメモリ上の定義かを区別しない。
- シーンから重複する配置値を除去。参加者ノードは対戦構成側に残し、フィールド定義へ参加者/チームを混ぜない。
- main.switch_fieldに通常の部屋切替と新encounter時の一時状態初期化を用意。
- 切替失敗時は現場を保持。成功時はHP・弾薬・装備・所持金・参加者を維持し、旧フィールドの弾・補給品・経路を破棄。
- 新フィールドに補給グループがなければ、その種類の自動補給は何も出さない。

## APIの範囲と残る制約

- 定義は初期配置。再訪時の壊れた壁・未取得品の保存、ランダム生成、ギミック生成器は未実装。
- 配置は実行時に作る。Editor上での配置プレビューは未実装で、原本は.tresを編集する。
- 有限矩形・出現余白等は検証するが、全地点の到達可能性やマップバランスは保証しない。
- 補給候補点の壁重複は従来どおり許可し、出現時に別候補を試す。全候補が塞がれば出現しない。
- 切替は同じ参加者数で行い、出現地点不足なら拒否する。参加者追加/削除やチーム変更は行わない。
- main.switch_fieldは同期的な境界操作。CombatSession.stepの途中から再入せず、戦闘更新の間に呼ぶ。
- 試合のphase/残時間/結果は切替で変更しない。new_encounterはActor一時状態の初期化指定であり、対戦の次ラウンド開始ではない。
- フィールド切替で補給出現タイマーは初期化するが、所持品/取得履歴や所持金は保持する。
- 実通信、階層進行、セーブ機能、人間の操作感評価は今回の範囲外。
