# ボス制作テンプレート

区分: 共通制作手順。新しいボスの設計・素材制作・実装・レビュー時に読む。今回の鋳造機から得た注意点を共通化するが、その攻撃数・時間・機械部品を全ボスの必須仕様にはしない。資料のチェックだけでは生成を実行しない。

[総合索引](../README.md) / [敵素材の共通規格](ENEMY_CREATION_TEMPLATE.md) / [敵・ボスの計画](../planning/ENEMY_BOSS_ART_PLAN.md)

## 1. 読む順番と記録先

1. 本書と[敵・ボス共通の品質基準](ENEMY_CREATION_TEMPLATE.md#7-敵ボス共通の品質基準)を読み、仕様票・素材台帳・比較用の基準を用意する。
2. [現行ルール](../design/GAME_RULES.md)と対象コードで、攻撃・状態遷移・報酬の現在地を確認する。
3. [音響基準](../AUDIO_BIBLE.md)、[音響manifest](../../assets/audio/asset_manifest.json)、既存素材を確認し、不足分だけ制作対象にする。
4. 生成する場合は[生成環境](../development/ASSET_GENERATION_SETUP.md)と[音響CLI](../../tools/asset_generator/README.md)等の対象手順を読む。

ボス別の仕様票と素材台帳は `docs/art/production/<boss-id>/README.md` に置く。提案はplanning、実装済みのゲーム動作はGAME_RULES、実装方法は[ACTOR_ANIMATION](../development/ACTOR_ANIMATION.md)、確認方法は[TESTING](../development/TESTING.md)へ反映する。個別資料の入口は[production索引](production/README.md)へ追加する。

## 2. 制作前の仕様票

|項目|記入内容|
|---|---|
|個性・世界観|名前・種族・生息環境・役割。他ボスとのシルエット／攻撃体験の違い。機械・原生生物等を区別|
|見た目の根拠|砲口、顎、脚、尾、炉心など、攻撃を担う部位。見える武器が攻撃で使われるか|
|視点・寸法|見下ろし角度、通常カメラ倍率での表示幅／高さ、接地原点、移動／被弾判定、影|
|部屋・入口|形状、家具、入口方向、到着位置、ボス初期位置、戦闘開始条件、出口封鎖・解放条件|
|動作方式|方向別コマ／関節パーツ／併用。方向数、可動部位、前後の描画順|
|攻撃の役割|接近を迫る・遠距離を牽制する・回避を促す等。各攻撃の安全な避け方と反撃機会|
|段階変化|移行条件、移行中の判定、動作・音・発光の変化、攻撃回数や速度の変更|
|開始・撃破・報酬|演出の時系列、スキップ／再挑戦、報酬の種類と個数、取得・満杯・退出条件|
|今回の範囲|制作する素材、流用するもの、未実装・未確認、完了条件|

入口とボスの位置は対で決める。上側から入場して背中や本体に重なる構造を避け、必要なら前室・入口方向の制約を設ける。大部屋では画面外のボスや弾、カメラ追従も確認する。

## 3. 攻撃ごとの対応表

攻撃ごとに1行を作り、通常・強化段階の差を記入する。距離条件だけを書いて終わらせない。

|攻撃ID・役割|選択条件・優先度|構え→発動→復帰の時間|追尾／狙い固定|移動・判定・威力|素材・発射原点|SEと発火時刻|中断・壁接触後の遷移|
|---|---|---|---|---|---|---|---|
|記入欄|距離・射線・再使用待ち・直前の攻撃|各区間と連発数|固定する瞬間まで|移動／弾／範囲を区別|方向別座標も記録|発射・着弾を分離|必ず次の状態を指定|

- 新しい攻撃を足したら全攻撃の選択を確認する。新攻撃が優先され続け、機銃など既存攻撃が出なくなる状態を避ける。
- 遠距離・近距離・射線なしでも進行できる選択肢を用意する。攻撃不成立なら追跡・位置変更などへ戻し、条件待ちのまま停止させない。
- 突進の終了、壁・家具への接触、移動失敗、連続突進の次段、対象の回避、段階移行、死亡の各経路に終了条件を置く。プレイヤーが近づくまで再開しない状態を検査する。
- 構えと身体の動きで攻撃を読めるようにする。床の予告マーカーは自動的な必須要件にしない。
- 威力だけを上げず、間隔・速度・密度・追尾・距離圧力を調整する。遠くから撃ち続けるだけで成立するか、回避後の反撃機会があるかを実戦で評価する。

## 4. 必要素材・アニメーションの台帳

次表をボス別に埋め、不要な項目には理由を書く。すべてを新規生成する必要はない。

|区分|検討する素材／動作|制作時の注意|
|---|---|---|
|本体|待機・移動・停止・方向転換|接地と実移動を同期。全身スライドや単なる拡縮を歩行の完成としない|
|攻撃部位|腕・脚・尾・顎・砲塔・武器・装甲|ピボット、親子、隠れる面、最大可動角、前後の重なりを定義|
|攻撃動作|構え・突進・連射・反動・復帰|方向別の武器向きと発射位置を一致させる|
|跳躍／叩き付け|沈み込み・上昇・空中・落下・着地|本体の高さと床の影を分離。衝撃波は着地等の発動瞬間に同期|
|段階移行|起動・変形・咆哮・暴走・発光|色のふわっとした切替だけにしない。移行開始／終了と攻撃再開を明確化|
|飛び道具|弾・ミサイル・砲弾・尾・閃光|大きさ・速さ・明るさで脅威を読ませる。見た目と判定の差を記録|
|命中・範囲攻撃|着弾爆発・衝撃波の輪・火花・煙・粉塵|発射とは別素材。床との遠近、輪の厚み、減衰、連続発生時の視認性|
|被弾・撃破|被弾反応・内部破壊・主爆発・破片・倒れ・残骸消失|機械と生物の表現を分ける。破片の着地・消去まで設計|
|報酬|箱の閉・半開・開・空、アイコン、出現・開封・取得VFX|接地原点と倍率を全コマで統一。箱本体にも跳ね・伸縮・揺れを付ける|

台帳の列: 素材ID／用途／方向・コマ数／原画寸法／切出し領域／接地原点・接続点／表示寸法／流用・新規／原本・派生レシピ／接続先／状態／確認資料。

生成シートのセルが均等とは限らない。実際の透明領域と輪郭から切出し・原点を登録し、隣のコマの混入を確認する。各コマの輪郭に合わせて個別に拡大縮小しない。砲口の高さと床平面の弾判定を区別し、前後左右の発射位置を確認する。全身画像の平面回転だけで方向別の立体表現を代用しない。

パーティクルは煙・火花・粉塵等に適するが必須ではない。既存のシート・コード描画・粒子から必要な方式を選び、発生数／寿命／同時上限を設け、ポーズと後始末を共通化する。

## 5. SE・BGMの設計票

|用途|音の考慮点|
|---|---|
|起動・移動・常時音|機械なら駆動・排圧、生物なら呼吸等。必要な場合だけループ。距離減衰、継ぎ目、ポーズ・撃破・退出時の停止|
|構え・突進|溜め・加速・風圧・接地を動作に同期。繰返し時の耳障りさを確認|
|機銃・全周斉射・主砲|軽い連射と重い一撃を区別。斉射の弾数分を同時再生しない|
|着弾・叩き付け|発射音とは分け、小着弾・大着弾・着地の重量を区別。同時着弾は間隔制限等で集約|
|段階移行・撃破|移行を1回、内部破壊と主爆発を別の時刻へ。退役後も撃破SEを必要な長さだけ継続|
|宝箱・報酬|出現・着地・開封・取得の瞬間を区別。満杯や再操作で取得音を重複させない|
|BGM|スピード感、盛り上がり、覚えやすい旋律。銃声・攻撃SEを覆わない音量と密度。開始・停止・勝利音への接続|

各音に素材ID、意図、尺、発火イベント、同時発音の単位と上限、音量、距離減衰、ループ、停止条件、試聴状態を記録する。

「重厚」は金属の高い響きを増やす意味ではない。砲声なら低い衝撃と短い減衰、炎なら「ボウ」という空気と燃焼、排圧なら「プシュー」等、聴こえてほしい材質を明記する。単独試聴だけでなく連射・弾幕・BGMの重なりでも確認する。APIのloop指定やインポート成功は、継ぎ目や音色の確認済みを意味しない。

生成数・dry-run・再生成・通信エラー時の扱いはAGENTSと音響CLIの規則に従う。過去の生成許可を次のボスへ流用しない。素材生成の依頼だけで音響基盤全体を変更しない。

## 6. 開始・撃破・報酬のつなぎ

- 現在の方針は開始・撃破の説明文を出さずアニメーションで伝える。通常HUDと操作案内は別。将来のカットインは追加仕様として扱う。
- 開始時は操作・双方の攻撃・被弾をどう止めるか決め、スキップ入力が射撃へ流れないようにする。再挑戦時の短縮も定義する。
- 死亡判定と敵の退役は即時。撃破表示は値のスナップショットで独立させ、消えたActorを参照し続けない。表示の爆発は明示仕様がなければ追加ダメージを持たない。
- 長い撃破演出と報酬の出現時刻を連動させる。敵の退役、箱の出現、取得、踏破は別の状態として管理し、相打ち死亡・再挑戦時の優先順位を決める。
- 宝箱は出現→着地→開封→中身の跳び出し→取得まで作る。現在は選択画面を使わず拾得方式。飛び出し中の取得やF押しっぱなしによる開封直後の取得を防ぐ。
- 飛び出し方向は右固定にしない。壁・家具を避け、複数なら着地点を分散し、再入室で変えない。箱とアイテムの位置、取得距離の整合を確認する。
- 現在の箱は1アイテム。複数用の方向計算はあるが、複数報酬の個別描画・取得・保存まで実装済みとは扱わない。追加する際は個々の取得状態と満杯時の残留を設計する。
- 満杯でも進行不能にしない。報酬を残して退出する条件、通貨を加算する瞬間、二重取得防止を決める。

## 7. 完了チェックと提出物

以下はボス固有の追加チェック。動き・見た目・SEの合否は敵素材テンプレートの共通品質レビュー票で判定する。長さ・明るさ・音量・素材数を増やしたことだけで品質向上としない。

- [ ] 全方向で発射原点・武器の向き・歩行接地・関節の隠れた面を通常倍率で確認。
- [ ] 各攻撃が実際に選ばれ、遠距離・近距離・射線なし・壁際で停止しない。
- [ ] 連続突進、着地、段階移行、攻撃途中の撃破、低フレームレートでも次状態へ進む。
- [ ] 予備動作と発射・着地・SEの時刻が一致し、弾と回避可能な空間が読める。
- [ ] 開始／スキップ／撃破／報酬の最中のポーズ・フォーカス喪失・復帰を確認。
- [ ] SEオフ、ループ停止、同時発音、BGMとの比率を実際に試聴。
- [ ] 満杯・再入室・二重操作・相打ち・退出・再挑戦で報酬と通貨が重複しない。
- [ ] 退役した敵の弾・判定・参照、残存VFX・ループ音を適切に消去。
- [ ] 通常倍率の静止画と連続動作記録、原本／加工レシピ／manifest／未確認事項を保存。
- [ ] 自動テスト・目視・試聴・ユーザー採用を別々に報告。Web／低性能端末の負荷も確認状態を明記。
